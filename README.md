# Wildfire State Engine - Technical Manual

## 1. Data Intake & Source Selection
The system ingests signals from three primary categories of sources, selected for their speed, reliability, and coverage.

### Sources
| Source Type | Specific Feed | Purpose |
| :--- | :--- | :--- |
| **Official RSS** | CAL FIRE, LAFD, InciWeb | **Ground Truth**. Verified ignition/containment data. |
| **Social Media** | Twitter (X) Parsers | **Speed**. Localized, real-time eyewitness reports (Video/Image). |
| **Simulation** | Internal Scenario Library | **Testing**. Generated diverse crisis events for system validation. |

### Relevant Captured Information
The intake layer parses unstructured text to extract:
*   **Geolocation**: District, County, or specific landmark (e.g., "Topanga Canyon").
*   **Hazard Type**: Fire, Smoke, Wind, Infrastructure Damage.
*   **Temporal Data**: Time of report to calculate "Freshness".

---

## 2. Processing & Scoring
The core logic resides in the `StateEngine` class, which employs a **Listen-Synthesize-Act** loop.

### The AI Cycle
1.  **Aggregation**: Signals are grouped by District.
2.  **Context Retrieval**: The engine fetches the *current* state of that district from Monday.com to maintain continuity.
3.  **Synthesis (Gemini LLM)**:
    *   **5-Point Analysis**: The LLM evaluates 5 dimensions:
        *   Human Safety (Evacuations, Threats)
        *   Infrastructure (Power, Roads)
        *   Intensity (Spread Rate, Size)
        *   Environmental (Weather, AQI)
        *   Operational (Resource requests)
    *   **Certainty Score**: Assigned 0-100 based on source reliability (Official > Social).
4.  **Filtering**: Updates with a Certainty Score < **60** are discarded to prevent noise.

## 3. Monday.com Integration
The tool acts as an autonomous agent that manages the "California Wildfire Incidents" board.

### Board Structure
*   **Item Name**: District Name (e.g., "Ventura", "Napa").
*   **Item Type**: Dynamic Operational Entity (persists and updates over time).

### Key Columns
| Column Name | Type | Description |
| :--- | :--- | :--- |
| **Magnitude** | Number | 1-10 Score reflecting overall severity. |
| **Response Status** | Status | `Act` (Red), `Watch` (Orange), `Monitor` (Blue), `Resolved` (Green). |
| **Deep Summary** | Long Text | High-level situation report generated by AI. |
| **Certainty** | Number | Confidence score of the current assessment. |
| **Extended Analysis** | Long Text (x5) | Detailed breakdown of the 5-Point Analysis (Safety, Infra, etc). |
| **Last Updated** | Date | Timestamp of the latest intelligence push. |

### Status Logic & Smart Routing
The engine calculates a `Magnitude` (Mag) and routes to the appropriate **Group**:

| Magnitude | Group Name | Status |
| :--- | :--- | :--- |
| **8 - 10** | `🚨 LEVEL 1: CRITICAL ACTION` | **Act** |
| **5 - 7** | `⚠️ LEVEL 2: HIGH WATCH` | **Watch** |
| **3 - 4** | `🔍 LEVEL 3: MONITORING` | **Monitor** |
| **1 - 2** | `✅ STABLE / CONTAINED` | **Resolved** |

### Automation Concept
**Trigger**: When `Magnitude` changes from <8 to >=8.
**Action**:
1.  Move Item to `CRITICAL ACTION` group.
2.  Notify "Emergency Response Team" (via Monday Notification).
3.  Change `Response Status` to "Act".

### Expected Human Action
*   **Monitor**: Review updates every 4 hours. No resource allocation needed.
*   **Watch**: Pre-deploy liaison officer. Verify with CalOES.
*   **Act**: **IMMEDIATE INTERVENTION**. Mobilize resources based on "Operational Response" column data.

## 4. Failure Modes & Mitigations
The system is designed to be resilient, but specific failure modes exist.

| # | Failure Mode | Impact | Mitigation Strategy |
| :--- | :--- | :--- | :--- |
| 1 | **Hallucination** | AI invents a fire based on ambiguous text (e.g., "fire sale"). | **Certainty Threshold**: Updates < 60% confidence are blocked. |
| 2 | **Stale Data** | Board shows "Critical" for a fire contained hours ago. | **Freshness Weighting**: Old signals degrade in value; new "Contained" signals override old "Active" ones. |
| 3 | **Group Ping-Pong** | Item rapidly flips between "Watch" and "Critical". | **Hysteresis**: Engine requires significant signal change to downgrade status. |
| 4 | **Location Confusion** | "Paris Fire" (Texas) mapped to "Parris" (California). | **Geofence Validation**: Logic rejects coordinates outside California bounding box. |
| 5 | **API Rate Limit** | Monday.com rejects updates during surge. | **Complexity Budgeting**: Configurable `COMPLEXITY_BUDGET` limits operations per cycle. |
